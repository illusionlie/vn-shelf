# Quality Guidelines

> Code quality standards for frontend development.

---

## Overview

Project ships with **no build step** — `public/` is served as-is via Worker Assets. `npm run lint` (ESLint over `src/**/*.js` + `public/js/**/*.js`) and `npm run test` (`node --test`) are the hard gate.

Vendor minified bundles (`public/js/vendor/*.min.js`) and `.cjs` helper scripts are **out of lint scope** by globs (`eslint.config.js` ignores `**/*.min.js`; `.cjs` does not match `public/js/**/*.js`). Do NOT lint-fix a minified bundle.

---

## Forbidden Patterns

- **Runtime third-party CDN `<script src="https://cdn...">`** in any `public/*.html`. All front-end runtime deps must be self-hosted under `public/js/vendor/`. (Supply-chain drift + availability single-point. See `alpineVersion` + `fetch:vendor` for the audit path.)
- **`{ headers: {...defaults, ...options.headers}, ...options }` merge order in `apiRequest`** — the trailing `...options` wipes the merged `headers`, losing the default `Content-Type: application/json` when a caller passes any `headers`. Always spread `...options` first, then set `headers` separately. See `public/js/api.js` `apiRequest`.
- **`Date.now()` as a unique id** for in-session counters (e.g. toast ids) — same-millisecond collisions make `removeToast` delete the wrong entry. Use a module-scoped monotonic counter (`let _seq = 0; const id = ++_seq;`) or `crypto.randomUUID()`.
- **`@click` on a non-focusable `<div>`** to open an interactive flow (e.g. a VN card). Either use a native `<button>` or add `role="button" tabindex="0"` + `@keydown.enter.space.prevent="..."` + `:aria-label`. A click-only `<div>` is invisible to keyboard users. (Tier cards already use `<button>`; index cards must add the role/keyboard attrs.)
- **Icon-only `<button>` with text content only (`&times;`, SVG).** Must carry `aria-label`. Same for toggle buttons: also `aria-expanded` + `aria-controls`.
- **Raising an `auto-fill` card grid's `minmax()` floor in a `min-width` widescreen tier without recomputing columns at the breakpoint's right edge.** Columns `N = floor((W + gap) / (min + gap))`, where W = `.container` content width (max-width 1500px, 1600px at ≥1024, minus 2×5% viewport padding, border-box). A bigger floor can DROP a column just above the breakpoint: `minmax(300px, 1fr)` at ≥1024 rendered 1024–1100px viewports as 2 giant 416px cards — fewer and larger than at 1000px (B6d root cause). When adding or tuning a wide tier, verify N and card width on BOTH sides of every breakpoint (method: per-viewport table like AC1 in task B6d's prd.md).
- **`flex-direction: column` on a multi-control toolbar in the mobile (`max-width:768px`) tier.** `.controls-bar` is a `flex-wrap: wrap` row at base; forcing `column` stacks EVERY child on its own line (search + sort + status filter + add button = 4 rows, wasting vertical space on a small screen). Correct mobile pattern: keep the wrap row, give the search box `flex: 1 1 100%` to own the first line, and let the remaining selects `flex: 1 1 0; min-width: 0` share the next line. Verify on a real ≤390px viewport for both admin (add button present) and guest states. (07-12 status-visual-refine.)

## Required Patterns

- **Self-hosted vendor with reproducible fetch script.** To add a runtime front-end lib: place the bundle under `public/js/vendor/<name>.min.js`, record its locked version as a root field in `package.json` (e.g. `alpineVersion`/`markedVersion`/`purifyVersion`), and add a `fetch:vendor` script that downloads by those versions and prints a sha256 per file for upgrade audit. The `.min.js` suffix is the lint-ignore entry — name consistently to fall under `eslint.config.js` `**/*.min.js` ignore. NOTE: `.min.js` here means "lint-ignored vendor file", not literally minified — when upstream publishes only unminified ESM (marked `lib/marked.esm.js`, dompurify `dist/purify.es.mjs`), the unminified ESM is saved AS `name.min.js`, flagged in the fetch script; renderer/callers `import` from it normally. ONE `fetch:vendor` script can pull multiple libs; alpine+marked+dompurify all live behind `public/js/vendor/fetch-vendor.cjs`.
- **`apiRequest` default header survival.** Default headers that must survive caller-supplied `options` are applied AFTER spreading `options`, never via a leading `headers` key that `...options` later overwrites.
- **API success payloads are the unified envelope — components destructure `res.data`.** Since B6c every route returns `{success:true, message?, data, ...extras}` (list endpoints carry top-level `total`(/`updatedAt`); `message` is informational and never consumed). `apiRequest` returns the full parsed payload; unwrapping happens at the component call site. Never add `res.data || res` style fallbacks — dual-shape tolerance masks backend contract drift. Error payloads stay `{success:false, error}` with NO `code`; full contract in `.trellis/spec/backend/conventions.md` ("API 响应信封").
- **Friendly error toasts via `friendlyErrorMessage(error, prefix)`.** User-facing error toasts MUST NOT leak raw technical text (`Failed to fetch` / `HTTP <status>` / server stack). Call `friendlyErrorMessage(error, prefix)` (in `api.js`): it returns `${prefix}${t('common.colon')}${friendly}` for 5xx/network/unknown (synthesized generic copy) and `${prefix}${t('common.colon')}${serverOrLocalMessage}` for 4xx/local-validation throws that already carry authored Chinese user-facing text (separator is locale-aware since B6b: zh '：' / en ': '). Premise: `src/utils.js errorResponse(message, status)` returns `{success, error}` with NO `code` field and the `error` string is already friendly — so 4xx messages are MORE precise preserved verbatim than a generic map. The raw `error.message` is only ever `console.warn`'d, never toasted unless it's a friendly authored string. `apiRequest` network failure is wrapped into `createApiError(0, {error:'网络请求失败', code:'NETWORK'})` so `Failed to fetch` never reaches a toast.
- **CSS module placement & link-order contract.** CSS lives in `public/css/` split modules; there is NO single `style.css`. `<link>` order per page is fixed: `base.css` → `forms.css` → `cards-detail.css` → page file — later files may override earlier ones (this reproduces the old single-file cascade). Rules for new styles:
  - A class used by JS-injected DOM (`layout.js` shell: progress bar / background overlay / toast / confirmDialog, `markdown.js` md-*, translation tags) or by 3+ pages goes in `base.css`. When ownership is unclear, hoist to the shared file — a page loading a few unused rules is cheap; a page missing rules for injected DOM is a silent visual break (this bit Modal and `settings-section`, both hoisted to base).
  - Breakpoints are `480 / 768 / 1024` only; responsive rules live in the SAME file as their component, not a central media block. Never reintroduce `700px`.
  - Adding a page's `<link>` set: copy the closest existing page and prune; never link a page file before the shared files.
- **Card cover images size by `aspect-ratio: 7 / 10`, never per-tier fixed heights.** `.vn-card-image` = `width: 100%` + `aspect-ratio: 7 / 10` + `object-fit: cover`: height derives from the actual column width in every tier, and the pre-load placeholder kills CLS. Works only because base.css keeps the global `img { max-width: 100%; height: auto; }` reset — any fixed `height: <px>` (base or media tier) overrides the ratio. Do not reintroduce per-tier `height` overrides: fixed heights made the crop ratio drift across tiers (0.70 / 0.57 / 0.64 before B6d) and cost one rule per tier to maintain. Grid tier semantics in `cards-detail.css`: the base `.cards-grid` rule IS the medium tier (769–1023), `min-width: 1024` is the large tier, 768/480 the phone tiers; density floors (currently 180 / 210 / 160 / 140 px) are product-tunable — when changing them, re-verify breakpoint edges per Forbidden Patterns.
- **List-rendered cover `<img>` must carry `loading="lazy" decoding="async"`** (07-19 cover-lazy-loading): applies to every cover inside an `x-for` grid — shelf cards (`index.html`), tier rows and the untiered grid (`tier.html`). Detail-modal covers open on demand and are in-viewport immediately, so they take `decoding="async"` only, never `loading="lazy"`. Lazy sizing is safe only because `aspect-ratio` reserves the box before load (bullet above) — if a new surface drops the ratio, lazy-load will reintroduce CLS there. Markdown images already do this in the renderer (`markdown.js`).
- **Keyboard focus comes from ONE global rule — never write per-component focus styles** (07-19 focus-visible-coverage): `base.css` defines `--focus-ring` (2px accent outline) and applies it via `:is(a, button, [role="button"], select, input, textarea):focus-visible` + `outline-offset: 2px`. New interactive elements get the ring for free IF they are a native element or carry `role="button"` — a click-handling `<div>` without a role gets nothing (this is the check when adding one). Mouse clicks never show the ring (`:focus-visible`, not `:focus`). Known deliberate exemption: `.form-input:focus` keeps `outline: none` because its accent border + 3px glow IS the focus indication. Component-level `:focus-visible` additions (e.g. `tier-add-placeholder` color shifts) may layer on top but must not set `outline` themselves.
- **Every decorative motion ships with a `prefers-reduced-motion: reduce` counterpart in the SAME file** (07-19 reduced-motion): each of base / cards-detail / stats / tier ends with a `Reduced Motion` media block neutralizing its transforms/animations (hover lifts, cover zoom, light sweep, shimmer, toast slide, modal scale, smooth scroll). Color/shadow/opacity transitions and the loading spinner are deliberately KEPT — reduce targets movement, not feedback. When adding new motion, add its reduce rule next to it. Gotcha: Alpine `x-transition` writes transforms as INLINE styles during the transition, which beat normal declarations — the `.modal { transform: none !important }` in base.css exists for exactly this; a new `x-transition` element needs the same `!important` treatment (or drop the directive) to honor reduce.
- **Rating color semantics: green (`var(--personal-rating-color)`) = personal rating, gold (`#FFD700` star + accent number) = VNDB rating — everywhere a rating renders.** The personal green is a theme token (07-19 rating-color-contrast), NOT a literal: light `#0d9448` / dark `#4ade80`, defined in `base.css` `:root` and `body.dark-mode`. The old single `#6bff6b` failed light-mode contrast (~1.3:1 on the frosted background). Contrast standard for these surfaces is AA **3:1** (rating numbers are 19-20px/700 = large text; the ★ is a graphical indicator), NOT 4.5:1 — a 4.5:1 green reads muddy-dark on the light glass (user-rejected `#166534`); light value must keep >= 3:1 against the card/modal glass (~`#f0f1f3` effective, current ~3.4:1) — re-verify if the light surface colors change. Never hardcode a green hex at a usage site; reference the token. Established in the detail modal (`.detail-stars.personal-rating`), extended to shelf cards (07-12 card-personal-rating-first): the card shows the personal rating FIRST and falls back to the VNDB rating. Contract: unrated is stored as `0` (both manual create and ulist import), so `(vn.personalRating || 0) > 0` is the display switch — helpers `hasPersonalRating(vn)` / `cardRatingText(vn)` in `vnShelf.js`, class hook `.vn-card-rating.personal-rating` in `cards-detail.css`. Precision: personal `toFixed(1)`, VNDB fallback `toFixed(2)`. Any new surface showing a rating must keep the green/gold source distinction — a personal-looking VNDB score misleads at shelf scan distance.
- **UI copy goes through `t()` (i18n), never hardcoded string literals.** All user-visible dynamic strings in JS (toasts, status maps, validation throws, confirm dialogs, aria-labels set from JS) MUST come from `t(key, params?)` in `public/js/i18n.js`. HTML static copy is ALSO fully migrated (B6b): any NEW static text in a page must carry a `data-i18n*` marker with the key present in BOTH dicts — the only whitelisted hardcoded copy is the settings language radio's native-script labels ("简体中文" / "English"), which are never translated by design (B6a).
  - **Contract**: `t(key, params?)` — two-level key `<domain>.<name>` (domains: `common/error/status/toast/prefix/validation/confirm/time/theme/markdown` + since B6b `nav/meta` and per-page `index/login/settings/stats/tier`); `{name}` placeholders interpolated from `params`, missing params keep the placeholder verbatim (deliberate, to surface bugs); fallback chain `current locale → zh-CN → key itself` with per-key deduped `console.warn`. `setLocale(locale)` persists to `localStorage['locale']` then lazy-`import('./locales/<locale>.js')`, falling back to zh-CN on load failure. `initI18n()` must run in `app.js` BEFORE Alpine component registration. `getStoredLocale()` returns the persisted preference (`localStorage['locale'] ?? 'zh-CN'`); `getLocale()` returns the locale of the currently LOADED dict — during the async dict import they differ, so UI state (e.g. the settings language radio) MUST bind `getStoredLocale()`, never `getLocale()` (B6a race lesson).
  - **Dictionary carrier is a JS module, not fetched JSON**: no build step + native ESM means `import ... from './locales/zh-CN.js'` is the only way to guarantee `t()` is synchronously usable at first frame (JSON import assertions have shaky browser support; `fetch()` introduces an async race). New language = one new `locales/<locale>.js` file mirroring zh-CN's two-level key structure + register it in `tests/public/i18n.keys.test.mjs` + add a radio option in settings' Language section — zero framework change. `en.js` is fully filled (B6a); the keys test asserts BIDIRECTIONAL leaf-key equality with zh-CN, per-key `{placeholder}` name-set parity, and non-empty string leaves — dictionary drift in either direction fails `npm run test`.
  - **Boundary — backend 4xx messages are NOT translated**: `src/utils.js errorResponse` returns authored Chinese `error` strings with no `code`; `friendlyErrorMessage` passes them through verbatim (branch 4). i18n covers frontend-authored copy only. Do not wrap backend messages in `t()`.
  - **Locale switching is refresh-effective by design**: `t()` is evaluated at call time (toast fire / render), not reactively; already-rendered text updates on reload. The shipped switcher (settings → Language section radio) does `await setLocale(x)` then `location.reload()` — switching IS the refresh. Do not "fix" this by making locale an Alpine reactive store without a task that needs live switching.
  - **HTML static text uses the `data-i18n*` dialect applied by `applyI18nDom(root = document)`** (B6b): `data-i18n="key"` sets `textContent`; `data-i18n-placeholder` / `-aria-label` / `-title` / `-content` set the matching attribute. Two hard rules: (a) **leaf-only** — a `data-i18n` (textContent) marker must sit on an element with NO child elements, because setting `textContent` wipes the subtree; a button containing an SVG marks its inner `<span>`, never the button. (b) **mutually exclusive with Alpine** — never put `data-i18n*` and the matching Alpine binding (`x-text` / `:placeholder` / …) on the same node/attribute; dynamic binding wins, the marker is omitted. `applyI18nDom` **recurses into every `<template>.content`** (Alpine `x-for`/`x-if` templates — ~42% of static copy lives inside them, and `querySelectorAll` does NOT descend into `template.content`), so cloned/stamped nodes inherit the translation from the template source. It also syncs `document.documentElement.lang = getLocale()`. Inline Chinese literals inside Alpine expressions (`x-text="cond ? '保存中...' : '保存'"`) are unreachable by the `t()` module import — use the `$t('key')` magic (registered via `Alpine.magic('t', () => t)` in `alpine:init`).
  - **i18n DOM apply wiring is order-sensitive and must NOT use top-level await** (B6b): `app.js` does `const i18nReady = initI18n(); injectShell(); applyI18nDom(); i18nReady.then(() => applyI18nDom());` — a synchronous first pass (zh-CN default users reach final state immediately; en users see a brief Chinese flash) plus an idempotent second pass after the async dict import resolves. Top-level `await` in `app.js` (an ESM module) is forbidden: its ordering against `alpine.min.js` (defer classic script) is not guaranteed, so Alpine could boot before `alpine:init` listeners register and lose all component registration. The second pass is idempotent because keys live in attributes and are never consumed.
- **Native `confirm()` is forbidden for new flows.** Use the global `await this.$store.app.confirm({ title, message, confirmText, cancelText, danger })` Promise dialog instead (the `confirmDialog` component injected by `public/js/layout.js`). Native `confirm()` blocks the UI, is un-stylable, and is keyboard-inaccessible; the ambiguous “OK=merge / Cancel=replace” antipattern is not allowed — use two explicit text buttons via `confirmText`/`cancelText`.
- **Modals need `role="dialog" aria-modal="true" aria-labelledby`** (on the panel `.modal`, NOT the `.modal-overlay` backdrop) + a focus trap (`trapFocus` from `utils.js`) on open + focus restore on close. `@keydown.escape` lives on the panel with `.stop` so a stacked confirmDialog does NOT cascade-close the content modal behind it — never rely on `window`-level Esc listener registration order.

## Testing Requirements

- Gate: `npm run lint && npm run test` must exit 0 before reporting a task complete.
- New front-end bug fixes should add a minimal assertion when feasible (e.g. header merge, unique id) — either as a `node --test` case or a documented manual check in the task PRD.

## Code Review Checklist

Front-end changes must pass these before commit:

- `npm run lint && npm run test` exit 0.
- No runtime third-party CDN; vendor self-hosted with `fetch:vendor` reproducible (see Required Patterns for the `.min.js` naming convention covering unminified ESM bundles).
- No native `confirm()` / `alert()` in new flows — use `$store.app.confirm`.
- Clickable `<div>` has `role=button tabindex=0 + @keydown.enter.space + :aria-label`, or is a native `<button>`.
- Modal has `role=dialog aria-modal aria-labelledby` on the panel + `trapFocus` on open + focus restore on close + panel-level Esc with `.stop`.
- Toggle button has `aria-expanded`/`aria-controls`; menus have `role=menu`/`role=menuitem`.
- `aria-live` region for transient status messages (toast).
- No new hardcoded user-visible string literals in JS — dynamic UI copy goes through `t()` with the key added to `locales/zh-CN.js` (see Required Patterns; HTML static text migration is a separate pending batch).
- Shared shell elements (progress bar / background / toast / confirmDialog) come from `public/js/layout.js` `injectShell()`, NOT copy-pasted per page. Header/nav stays per-page (active nav + per-page actions differ).
- Injected shell DOM reproduces the original markup byte-for-byte (same classes + Alpine directives) to avoid style regressions.
