# B6d 卡片条目缩小 + 三档响应式细化

> 父任务 `07-09-b6-finish`。纯 CSS，建立在 B5c 断点体系上。种子 PRD，正式规划在 start 前补全。

## Goal

缩小 VN 卡片条目尺寸，并把响应式从当前"桌面/移动两态感"细化为明确三段：大显示器 → 中等（办公显示器/平板）→ 手机。用户反馈 768px 断点仍偏大、卡片偏大。

## 已知约束（B5c 现状）

- 断点体系（B5c）：`480 / 768 / 1024`，规则跟随组件所在文件。
- 卡片栅格 `cards-detail.css`：默认 `.cards-grid` = `repeat(auto-fill, minmax(280px, 1fr))`；768 档 `minmax(160px,1fr)`；480 档 `minmax(140px,1fr)`；1024 档 `minmax(300px,1fr)`。
- `.vn-card-image` 等尺寸随档位调整。
- link 顺序与模块归属契约见 `.trellis/spec/frontend/quality-guidelines.md`（B5c 沉淀）——本任务改 cards-detail.css 为主。

## Requirements（草案）

- R1 缩小卡片条目默认尺寸（`minmax` 下限、图片高度、内边距）——使同屏容纳更多条目。
- R2 明确三段式响应式：
  - 大显示器（宽屏，≥ 某阈值）：多列、卡片可略大
  - 中等（办公显示器/平板，约 768–1200）：中等列数——**当前缺这一档的针对性优化，是本任务核心**
  - 手机（窄屏）：单列/双列紧凑
- R3 断点值可调整（用户觉得 768 偏大 → 可能引入中间档或下调）；与 B5c 既有 480/1024 协调，不留 700px 类残留。
- R4 视觉不破坏（深色模式、详情弹窗、Tier 卡片区一致）。
