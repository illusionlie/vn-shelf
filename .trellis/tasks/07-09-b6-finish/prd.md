# PRD — B6 收尾批次（父任务）

> 承接 B5 批次收官后的四项遗留/新增工作。本父任务**不做实现**，仅统领子任务边界、依赖与最终集成验收。实际工作交付四个独立可归档的子任务。

## 范围拆分

### B6a i18n 收尾（`07-09-b6a-i18n-finish`）
- 填充 `public/js/locales/en.js` 英文词典（对齐 zh-CN 全部 key）
- 新增 key-diff 单测：断言 en 键集 ⊆ zh-CN 键集（防漏译/键漂移）
- 设置页新增语言切换入口（下拉或按钮，调 `setLocale` + 持久化）
- 承接 B5b 设计文档明确记录的三项后续；规模 S–M

### B6b HTML 静态文案 i18n 迁移（`07-09-b6b-html-i18n`）
- 五个 HTML 约 237 行静态中文（导航、placeholder、`<option>`、aria-label、title/meta）纳入 i18n
- B5b 仅迁 JS 动态文案，HTML 当时明确留作本灰度批次
- 需要 i18n 框架支持 DOM 扫描应用（`data-i18n` 或等价机制），属对 i18n.js 的能力扩展；规模 M
- 依赖 B6a（en 词典就位后 HTML 切换才有意义，但非强依赖：可先迁 zh-CN 键）

### B6c 后端 API 信封统一（A3）（`07-09-b6c-api-envelope`）
- 所有 API 路由返回统一信封 `{success, data, ...}`
- B5a 时前端已删 `|| res` 兜底并核对，后端真正统一是独立后端任务，一直未做
- 后端改动 + 前端读取形态核对（可能回填前端解构点）；规模 M；**跨层，需 code-spec 深度**

### B6d 卡片缩小 + 三档响应式细化（`07-09-b6d-responsive`）
- 现状问题：768px 断点仍偏大，卡片条目偏大
- 缩小卡片条目尺寸；建立"大显示器 → 中等（办公显示器/平板）→ 手机"三段式响应式
- 在 B5c 已有的 480/768/1024 断点体系上细化（可能调整断点值与各档栅格密度）；规模 M

## 范围外

- 不引入第三方 i18n / CSS / 打包库（延续 B5 自托管原则）。
- 不做视觉重设计——B6d 限于尺寸与栅格密度调整，不改设计语言。

## 子任务依赖

- **B6a 独立**（纯前端 i18n 增量）。
- **B6b 依赖 B6a**（en 词典就位后 HTML 切换才完整；可先迁键后补译）。建议顺序 B6a → B6b。
- **B6c 独立**（后端为主，跨层核对前端读取）。
- **B6d 独立**（纯 CSS，建立在 B5c 断点体系上，与 i18n/后端不冲突）。
- 四子任务大体可并行；建议顺序 B6a → B6b → B6d → B6c（前端连续、后端压轴），或按用户优先级调整。
